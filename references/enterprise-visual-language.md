# 企业界面视觉语言

`PROJECT-DEFAULT`：用于桌面 Web 的可调整视觉配方，重点是清晰层次、紧凑排版、轻质表面与稳定对齐。只提供设计元素和组合原则，不包含特定产品名称、业务模块或操作流程。已有品牌、组件库和用户参考优先；不要求所有界面使用蓝色或同一套布局。

## 1. 表面与色彩层次

- 用冷灰画布承托白色内容面板，浅底色区分工具栏、表头和辅助信息。
- 深色用于建立局部视觉重心，强调色用于选中、链接和主操作；不要把所有容器都涂成强调色。
- 面板轮廓由细边框、轻阴影与底色差共同建立，避免白底叠白卡后边界消失。
- 需要柔和质感时，外围框架可使用低强度渐变或半透明白色；正文、表格和复杂表单保持稳定底色。模糊不可用时仍应清晰分层。
- 点阵、光晕等纹理只作为低对比背景细节，不承担信息，也不作为必选装饰。

## 2. 字体、密度与尺度

以下色值与尺寸是一套可用起点，不是跨项目的硬性标准；将其映射到项目已有语义 token。

| 角色 | 示例值 | 使用方式 |
|---|---|---|
| 页面 / 面板 / 弱底色 | `#eef3f7` / `#ffffff` / `#f8fafc` | 画布与内容分层，表格保持稳定底色 |
| 正文 / 次要文字 | `#101828` / `#667085` | 正文与元信息，浅灰不用于关键提示 |
| 品牌 / 主操作 | `#1e3a8a` / `#2563eb` | 品牌结构与选中、链接、主按钮 |
| 选中底色 / 文字 | `#eff6ff` / `#1d4ed8` | 浅蓝承载选中状态，附边框/勾选 |
| 成功底色 / 文字 | `#ecfdf5` / `#0f766e` | 可继续处理的状态 |
| 警告底色 / 文字 | `#fffbeb` / `#9a6700` | 待确认或不完整状态 |
| 失败底色 / 文字 | `#fef3f2` / `#b42318` | 阻塞与失败 |
| 面板边线 / 控件边线 | `#dfe6ee` / `#cbd5e1` | 弱边框分区；交互轮廓另按对比度验证 |

普通文字按 Web AA 对比度检查实际组合，半透明层按实际合成背景验证。不要直接把 warning 当实色填充再默认配白字。

- 字体：复用现有字体；新建可用 `Inter, Geist, system-ui, "PingFang SC", "Microsoft YaHei UI", sans-serif`。未安装字体会回退，不能假定已经加载 SF Pro。
- 桌面正文参考 13–14px，标签 12px，分区标题 18–21px；主页标题可适当放大，但数据处理页不使用营销级大标题。转为 rem 时以项目根字号为准。
- 桌面控件建议 32–36px 起步，表格行 36–44px 起步；多行内容允许增高，触控模式增大命中区域。紧凑不等于缩到不可读。
- 结构间距 16/24px、内部 8/12px、页边 20–32px 为起点；窗口窄时减少页边，再重排列。
- 小控件 8–12px 圆角，大容器按密度选 16–28px。阴影优先轻微，辅以边框，不给每一层重复投影。
- 轻玻璃可用于导航或外围框架；表格和复杂表单使用稳定白底。禁用模糊时仍有明确边界。
- 数字使用 tabular-nums，金额右对齐并显示币种/单位；0、缺失、加载中分别呈现。

## 3. 组件组合原则

### 卡片与网格

卡片内部按短标签、标题、说明、状态与动作建立层级；只有实际需要的内容才占位。多个卡片保持内边距、标题基线和动作位置一致，长说明允许自然换行，不靠缩小字体强行对齐。

中等密度卡片可从 18px 圆角、20px 内边距、14–16px 网格间距起步；容器宽度和内容长度决定列数。较宽的介绍区域可使用 34–46px 标题，与紧凑内容区域形成层次；不要把这种标题尺度套到数据处理区。

### 工具栏与数据表格

工具栏用浅底色与数据区分层，搜索、筛选、视图切换和操作按用途分组。优先保持控件高度、文字基线和组间距一致；窗口变窄时整组换行，而不是把文字挤碎。

表格使用克制的表头底色、细分隔线和清晰悬停/选中态。文本左对齐，数量与金额右对齐；弱化重复装饰，保留需要比较的字段。横向滚动发生在表格容器内，不撑宽整个页面。

### 主内容与辅助面板

只有存在需要同时查看的辅助内容时才使用双栏。主区占弹性宽度，辅助区可从 300–320px 起步；辅助标题带可以局部使用深色建立重心，其余内容保持轻质表面。空间不足时收为单列，保留阅读与操作顺序。

### 状态与反馈

状态通过文字、形状和颜色共同表达，选中态与警告态不可混淆。错误提示的视觉权重应高于普通说明。进度条或步骤指示器仅在真实多步交互中使用，不作为页面装饰。

## 4. 布局实现片段

类名仅示意，移植时复用项目组件与 token；示例断点按内容开始拥挤的位置调整。

```css
.content-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(18rem, 20rem);
  gap: 1.125rem;
  align-items: start;
}
.content-main { min-width: 0; }
.table-scroll { max-width: 100%; overflow-x: auto; }
.table-scroll table { width: 100%; border-collapse: collapse; }
.numeric { text-align: right; font-variant-numeric: tabular-nums; }
@media (max-width: 72.5rem) {
  .content-layout { grid-template-columns: minmax(0, 1fr); }
}
```

保留原生表格语义。吸顶表头、固定列和浮层不能遮挡键盘焦点。模态与非模态面板按各自交互语义实现，不因外形相同而共享错误的焦点约束。

## 5. 视觉检查

- 画布、内容面板、工具栏、数据区的层级是否可辨？
- 字号、字重、颜色是否共同表达主次，而非只靠放大标题？
- 卡片与控件的圆角、间距、基线和边线是否一致？
- 装饰是否压过内容，或挤占主要操作空间？
- 长中文、窄窗口和放大后能否保持完整内容与操作可达？

组件的筛选、选择、详情与数据状态另见 [工作台交互](../patterns/workbench.md) 和 [状态与表单](states-and-forms.md)，不要从视觉配方推导业务流程。
