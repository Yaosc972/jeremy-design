# Motion(动效)
> 来源: https://developer.apple.com/design/human-interface-guidelines/motion
> 整理自 Apple HIG 原文(2026-09 抓取)。规范条目忠实原文,未新增规则。

优美流畅的动效让界面活起来:传达状态、提供反馈和引导,丰富 App 或游戏的视觉体验。

许多系统组件自带动效,让你在整个 App 或游戏中提供熟悉且一致的体验。系统组件还会根据辅助功能设置、不同输入方式等因素调整动效。例如:Liquid Glass 的运动在直接触摸时以更强的幅度回应,强化触感体验;而用户用触控板交互时,效果则更含蓄。

如果要设计自定义动效,请遵循以下规范。

## 最佳实践

- **有目的地添加动效,支持体验而不喧宾夺主。** 不要为动效而动效。无理由或过度的动画会分散注意力,还可能让人感到脱节或身体不适。
- **让动效可选 (Make motion optional)。** 不是每个人都能或愿意体验 App/游戏中的动效,所以**务必避免把动效作为传达重要信息的唯一方式**。为了让所有人都能享受你的 App 或游戏,在视觉反馈之外,同时使用 haptics(触觉反馈)和 audio(音频)等替代方式来传达信息。

## 提供反馈 (Providing feedback)

- **追求跟随用户手势与预期的真实反馈动效。** 在非游戏 App 中,准确、真实的动效能帮助人们理解事物如何运作,而不合情理的反馈动效会让人迷失方向。例如:如果用户是通过从顶部向下滑动来显现一个视图,他们不会预期通过向侧边滑动来关闭它。
- **反馈动画力求简短而精确。** 简短精确的动画感觉轻量、不打扰,往往比显眼的动画更有效地传达信息。例如:游戏中与成功操作精确绑定的简短动画,玩家瞬间领会信息而不被拉离游戏;再如 visionOS 中,点击 Photos 的全景图时,它快速平滑地展开充满眼前空间,让人跟上过渡又不必干等。
- **App 中,通常避免给高频 UI 交互添加动效。** 系统已为标准界面元素的交互提供细微动画。对于自定义元素,通常要避免让用户每次交互都花额外时间注意不必要的动效。
- **让用户可以取消动效 (Let people cancel motion)。** 尽可能不要强迫人们等一个动画播完才能进行其他操作——尤其是需要反复经历的动画。
- **考虑在合适之处使用 animated symbols(动画符号)。** 使用 SF Symbols 5 或更高版本时,可对 SF Symbols 或自定义符号应用动画。(参见 Animations)

## 借助平台能力(游戏)

- **确保游戏的动效在每个支持平台上默认表现良好。** 多数游戏中,保持 30 到 60 fps 的稳定帧率通常就能带来流畅、美观的体验。在每个支持的平台上,利用设备图形能力启用默认设置,让人们无需先改设置就能享受游戏。
- **让用户自定义游戏的视觉体验,以优化性能或续航。** 例如:当系统检测到外接电源时,允许用户在不同性能模式间切换。

## 平台差异

> iOS、iPadOS、macOS、tvOS 无额外注意事项。

### visionOS
在 visionOS 中,动效除了细微传达语境、吸引对信息的注意、丰富沉浸体验之外,还可与 Depth 结合,在人们注视交互元素时提供关键反馈。由于动效很可能在 visionOS 体验中占很大比重,避免造成分心、困惑或不适至关重要。

- **尽可能避免在视野边缘 (edges of the field of view) 显示动效。** 人们对周边视觉中的运动特别敏感:除了分心,还可能引起不适——让人感觉是自己或周围环境在动。如果沉浸体验中必须在周边区域展示物体移动,确保该物体的亮度与可见内容其余部分相近。
- **展示大型虚拟物体移动时,帮助人们保持舒适。** 当物体大到充满大部分 Field of view、遮挡大部分或全部 Immersion 和 passthrough 时,人们会自然把它当作周围环境的一部分。为了不让人觉得是自己或环境在动,可以增加物体的半透明度让人看透它,或降低其对比度让运动不那么显眼。

  > **Note:** 即使移动大型虚拟物体(如窗口)的是用户自己,也可能产生不适。虽然调整半透明度和对比度在此场景下有帮助,也应考虑让窗口的尺寸保持较小。

- **需要把物体移到新位置时,考虑使用 fade(淡入淡出)。** 物体移动时人们会自然注视其移动轨迹;如果这种移动不传达任何有用信息,可以让物体先淡出、到达新位置后再淡入。
- **一般避免让用户旋转虚拟世界。** 虚拟世界旋转时,体验通常会打乱人的稳定感——即使旋转由用户控制且移动很细微。替代方案:在快速 fade-out 期间使用瞬时方向变化。
- **考虑给人们一个静止的参照系。** 视觉运动被限制在一个不移动的区域内时,人们更容易接受;反之,如果整个周围环境看起来都在动(例如游戏自动带着玩家在空间中移动),人们可能感到不适。
- **避免展示持续振荡 (oscillate) 的物体。** 尤其要避免频率约 0.2 Hz 的振荡——人们对这一频率非常敏感。如果必须展示振荡的物体,尽量保持低振幅,并考虑让内容半透明。

### watchOS
SwiftUI 为 App 添加动效提供了强大而精简的方式。如果需要用 WatchKit 动画化布局与外观变化——或创建动画图像序列——参见 WKInterfaceImage。

> **Note:** 所有布局与外观类动画自动内置动画起止时的 easing(缓动);无法关闭或自定义 easing。

## 数值速查

| 主题 | 数值/规则 |
|---|---|
| 游戏目标帧率 | 30–60 fps 稳定帧率通常即可流畅 |
| 禁忌振荡频率 | 约 0.2 Hz(人对该频率非常敏感,避免持续振荡) |
| 振荡处理 | 低振幅 + 考虑半透明内容 |
| visionOS 周边动效 | 尽量避免;必须展示时物体亮度与周围内容相近 |
| 大型虚拟物体移动 | 提高半透明度或降低对比度;窗口尺寸宜小 |
| 旋转虚拟世界 | 一般避免;可在快速 fade-out 中做瞬时方向变化 |
| SF Symbols 动画 | SF Symbols 5+ 支持 animated symbols |
| watchOS easing | 内置、不可关闭/自定义 |
