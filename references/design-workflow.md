# 设计任务启动流程（写页面前先定方向）

> **性质**：`PROJECT-DEFAULT` 工程方法。本文件是任务启动的工作流约定，不是 Apple 官方规范；它决定"读哪些 reference、先做什么结构"，不替代各 reference 中的具体数值。

## 0. 五问：动手前先确定

1. **谁使用**——终端用户 / 内部员工 / 管理员？主要输入方式是鼠标、触控还是键盘？
2. **最重要的任务**——用户打开这个页面**最常做的第一件事**是什么？
3. **有哪些真实内容**——真实数据形态：长列表、大数字、长文本、常见空态？
4. **属于哪类产品**——内容网站 / 工作台 / 移动 Web（见 §2 分流表）
5. **是否已有设计系统**——项目现有的 tokens、组件库、样式约定

## 1. 信息的获取要克制

- 能从项目中读到的（现有代码、样式文件、README）**直接读取**，不问用户。
- 缺少但可合理默认的，**明确采用默认值并标注**（如"字号与间距按 `PROJECT-DEFAULT`"）。
- **只有影响方向的关键缺口才提问**——如"给内部员工还是外部客户""数据量级是几十行还是几十万行"。不要给用户发问卷。

## 2. 同一设计语言下的三类任务

三类任务都先采用 [Apple Web 设计基础](apple-web-foundation.md)。下面只区分内容组织、密度和交互，不用页面类型切换视觉风格。

| 模式 | 首要设计目标 | 读哪个文件 |
|---|---|---|
| **网站 / 内容页面** | 看懂内容、建立信任、完成下一步 | 本文件 §3 + `layout.md` / `typography.md` |
| **工作台 / 后台** | 高效查找、比较、编辑和处理数据 | `../patterns/workbench.md` + `enterprise-visual-language.md` |
| **移动 Web** | 小屏与触控下顺畅完成任务 | `../patterns/mobile-web.md` |

这三种模式是**本 skill 建立的项目设计模式，不是 Apple 官方规定的模板**。同一产品可以混合（桌面工作台 + 移动端），分流按**本次任务实际交付的界面**定。

## 3. 网站 / 内容页面的核心内容

- **内容节奏**：首屏回答"这是什么、为什么值得看"；向下逐层给证据与细节，不堆砌。
- **阅读宽度**：正文行宽控制在约 45–75 字符（中文约 25–40 字），超出用容器约束。
- **导航**：主导航层级浅而稳定；当前所在位置可见。
- **图片与正文关系**：图服务于文，配图与相邻段落主题一致；不留"装饰性占位图"。
- **行动入口**：主行动（CTA）在每个自然停顿点可得，且一页只有一个首要行动。

## 4. 先结构，后视觉

先把"用户来做什么"映射成页面结构，再选视觉表达：

- 用户主要来**处理待办** → 首屏优先待处理事项和操作入口。
- 用户主要来**理解产品** → 首屏优先价值说明与产品展示。
- 用户主要来**比较数据** → 优先比较维度、筛选条件和数据展示。

反面模式：先决定"大圆角、玻璃栏、四个统计卡片"再往里塞内容。视觉风格服务于**内容和任务**，不是反过来。

## 5. 已有设计系统的项目：复用优先

- 项目已有 tokens / 组件库时，**优先复用**，不另造一套几乎相同的颜色、间距和圆角（同样见 `web-tokens.md`）。
- 局部修复任务**保留原有结构**；改版范围由用户目标决定；只有新建或明确改版才重建整套视觉方案。
- 参考复刻任务**忠实于参考**，忠实度优先于个人偏好。

## 6. 与 SKILL.md 执行流程的关系

SKILL.md 的“先判断，再设计”在这里展开：本文件负责"定方向"，各 reference 负责"定数值"，`detail-audit.md` 负责"交付前验收"。
