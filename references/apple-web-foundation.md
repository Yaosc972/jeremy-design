# Apple Web 设计基础

本 skill 所有页面类型共用的默认设计方向。以下是受 Apple 设计理念启发的 `PROJECT-DEFAULT` / `WEB-ADAPTATION`，不是 Apple 官方规定的网页配方；原生平台参数按需查 [Apple 速查](apple-quick-reference.md)。用户要求和已有项目设计系统优先。

## 共同语言

- **内容优先、框架轻盈。** 默认用浅中性画布、白色或轻质面板、清晰文字层级承托内容。导航服务定位，不用整块高对比背景抢走主要任务的注意力。
- **精致来自组织。** 依靠留白、对齐、字重、细分隔和适度圆角形成层次；不是把文字都变浅、把警告都变淡，也不是给每个区块加阴影。
- **强调色有明确职责。** 用于主操作、当前选中和必要状态；导航父级可以弱提示展开关系，当前子项才是主要选中态，避免两层都铺高饱和底色。
- **材质有边界。** 轻微半透明或模糊可用于导航、工具栏、浮层；表格和表单内容有稳定底色。无模糊时仍能辨认边界，不把玻璃、光晕或渐变当作 Apple 风格的必选装饰。
- **交互连续、反馈明确。** 保留上下文、可见焦点、及时且可恢复的反馈；动效用于解释状态变化，遵循减少动态效果偏好。

## 工作台是同一语言的延伸

紧凑工具栏、模块入口卡片、任务摘要、数据表格、主辅分区和轻质表面，可以共同组成 Apple 风格的数据工作台。根据任务提高信息密度，不切换到另一套“企业蓝”模板；详见 [工作台元素](enterprise-visual-language.md)。

未指定其他方向时，导航从浅色中性表面开始，用细分隔、文字字重和低强度选中底色定位。不要从“企业”“专业”“后台”推导出藏青侧栏、蓝色渐变或发光按钮。深色主题或品牌框架仍可在用户参考或项目规范支持时采用，不把深色本身判为错误。

桌面紧凑控件与移动触控采用不同尺度，但保持相同的字体层级、状态语义和材质逻辑。不要照搬原生 point 数值、强加手机布局、SF 字体下载或全套原生组件。

## 应用时的判断

先说明本次如何将共同语言用于当前任务：哪些内容优先、哪些入口需要突出、密度如何选择、原有设计特征如何保留。不要把“采用 Apple”缩减为换字体、变灰白或套固定配色。

改版仍按 [改版检查](redesign-checks.md) 验证；视觉统一不能以丢提示、挤坏卡片或隐藏导航为代价。
