# 细节审查矩阵（交付前强制）

前端交付的"细节事故"——字号档位下折行、孤字、文字重叠、水平溢出——都不是审美问题，是**功能缺陷**。它们只在特定窗口宽度 × 字号 × 外观的组合下出现，肉眼单档位检查必然漏掉。本节把"反复审查"做成可执行的机械化流程：**跑矩阵 → 读结果 → 修 → 复跑**，全绿才允许宣称完成。

## 一、工具

```
scripts/detail-audit.js    注入式检测器，调用 AUDIT() 返回四类检测结果
scripts/audit-matrix.sh    矩阵运行器，多档位自动跑并汇总
```

用法：

```bash
# 每档写一个小 JS（页面 load 后 400ms 执行），如
echo 'for(let i=0;i<5;i++)document.getElementById("dtPlus").click()' > dt150.js
echo 'document.documentElement.dataset.theme="dark"' > dark.js
echo 'if(typeof setRM==="function")setRM(true)' > rm.js

./scripts/audit-matrix.sh page.html dt150.js dark.js rm.js
# → 每档输出 {"o":溢出,"t":挤字,"ov":重叠,"w":折行} 计数 + 明细
```

运行器自动处理：headless Chrome 注入 → 强制激活 `prefers-reduced-transparency` 分支（headless 无法模拟该系统设置）→ 状态 JS 生效后 2.4s 读取快照（等过渡动画结束）→ 从 `document.title` 回传 JSON。`$CHROME` 环境变量可覆盖浏览器路径。

## 二、四类检测

| 代号 | 事故 | 判定 |
|---|---|---|
| `o` | 页面水平溢出 | `scrollWidth - innerWidth > 0` |
| `t` | 字形挤压 | `line-height < 字号 × 0.95`（固定 px 行高不随字号缩放时出现） |
| `ov` | 文本视觉重叠 | 两个文本矩形横向重叠 >35% 且纵向 >50% |
| `w` | CJK 拆词折行 | ≥2 行且存在 ≤2 字符的行（四字标签拆 3+1、孤字行） |

检测器的误报规避逻辑（改检测代码前必读）：只遍历直接子文本节点、逐字符 Range 测行、行聚类用邻近算法、含 `<br>` 豁免、80 字符上限、动画/不可见子树跳过——细节见 `detail-audit.js` 文件头。

## 三、验收矩阵（最低要求）

- **字号档位 ≥3 个**：100% / 150% / 200%（页面支持越多档越要覆盖，包括中间档）
- **外观 × 降级**：亮色、暗色 × reduced-transparency 开/关
- 响应式页面另加窄视口（320-390px）跑一遍

**每一档都必须 o/t/ov/w = 0。** 任一档非零即未完成。

## 四、核心纪律

1. **"特定档位窗口"型事故真实存在**：实测过只在 180% 拆、170%/200% 都正常的案例（"设置页"三字 2+1）。**单档位通过不构成交付依据**，必须矩阵。
2. **每轮修复后复跑全部档位**：修复（如给某元素 `nowrap`）常常把压力转移到邻居元素，制造新事故。修一个必须复跑全部。
3. **修完全部档位后目视复核关键截图**：检测器抓的是几何事实，不会判断"这样修好不好看"。改过布局的元素（列数变化、换行策略变化）截图确认观感没退化。
4. **不要为通过检测而过度修复**：1.5x 原本正常的布局，不要因为别的档位出事就顺手改掉。修法要**精确命中出事的档位窗口**（如加 `body.dt-xl` 类只作用于 ≥1.6x），不要波及正常档位——实测过把 1.5x 六列色卡擅自改成 3 列的事故。

## 五、修复决策树

| 症状 | 常见根因 | 修法 |
|---|---|---|
| `w` 短标签拆行 | 容器过窄/字号放大后文字超宽 | ① `white-space:nowrap` 保护（容器必须 `flex-wrap:wrap` 让不开就换行）；② 超长单元拆成 ≤容器宽的语义片段再各自 nowrap |
| `w` 中文段落孤字 | 行尾落单字 | `text-wrap:pretty` / `text-wrap:balance` |
| `w` 长句在窄单元折行难看 | 词边界差 | `text-wrap:balance`（短标题/表头效果最好） |
| `t` 字形挤压 | 固定 px 行高不随字号缩放 | 行高改 `calc(Npx * var(--dt))` 跟字号同步缩放 |
| `ov` 文本重叠 | 固定 px 容器高度装不下放大后的字 | 容器高度同样 `calc()` 缩放；检查所有固定尺寸部件是否都被字号驱动 |
| `o` 水平溢出 | 元素最小宽度 > 容器 | 移除 `min-width`/放宽 grid 列数；长代码/URL 用 `nw` 保护后再审视 |
| 表格被长词撑横滚 | 单元格内专名不可拆 | 专名包 `.nw`；表格整体允许 overflow-x 滚动属正常，但内页不应因此产生页面级溢出 |

**修法优先级**：内容层保护（nowrap/nw/br）> 布局层响应（wrap/balance/grid 列数）> 档位隔离（媒体查询或类）> 改字号数值（最后手段，会破坏设计比例）。

## 六、常见系统性根因（实战积累）

1. **字号缩放体系里的固定 px**：页面有 `--dt` 缩放变量时，任何不乘 `var(--dt)` 的固定尺寸（行高、图标容器、chip 高度）都会在大档位挤字/重叠。新增组件时**每一个 px 尺寸都要过一遍"它要不要跟 --dt 缩放"**。
2. **`inline style` 打不过类 CSS**：修改响应式规则要落到类上（媒体查询/档位类），行内 style 无法被媒体查询覆盖——发现事故元素带 inline style 时先清理。
3. **死规则**：写了 `body.dt-lg .sw-grid{...}` 但页面里所有网格都带更高特异性的 `.sw6`——规则永不生效。加响应式规则后 grep 确认特异性链路，或直接实测该档位是否变化。
4. **动态写入组件的时机**：JS 在动画循环里持续写 DOM 的组件（转轮、计数器），检测脚本要等状态稳定后再读（运行器固定 2.4s 等待）；对手写注入脚本，确保先触发状态再等到动画结束后取值。
5. **平衡换行的代价**：`text-wrap:balance` 在中英混排长段落里有浏览器行数上限（超出即静默失效），长文案仍可能孤字——以矩阵实测为准，不假设规则生效。

## 七、和 web-adaptation.md §4 的关系

§4 讲**对策**（nowrap/nw/pretty/balance 怎么写），本节讲**验证**（怎么确认对策在全部档位真的生效）。写之前读 §4，交付前跑本节矩阵。
