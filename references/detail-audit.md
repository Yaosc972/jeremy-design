# 细节审查（交付前执行，分级验收）

前端交付的"细节事故"——字号放大/重排下的文字裁切、孤字、重叠、溢出——不是审美问题，是**功能缺陷**。它们只在特定状态组合（字号 × 外观 × 视口 × 数据状态）下出现，肉眼单档位检查容易漏掉。本节把"反复审查"做成可执行的机械流程：**跑矩阵 → 读结果 → 分级处置 → 复跑**。

**验收口径：阻断问题清零；警告逐项复核并记录处置；不以消除所有启发式告警为目标修改正常布局。** 审查器辅助设计判断，而不是让设计迎合审查器。

## 0. 先选验证范围

新建与改版都先执行 [成品自检](finished-ui-check.md)：实际触发相关状态、检查并看图、修复后复测。本文件的几何检测是其中一部分，不负责单独判定交付完成。

- 文档/skill 改动：校验入口、引用和指令一致性；不为了文档改动启动业务服务。
- 局部视觉修复：检查被改组件、相关状态、目标窗口及放大后的布局；复用当前版本的有效证据。
- 新页面或布局改版：检查主要任务、正常/空/错/长内容状态、目标桌面窗口与窄窗口、200% 放大；存在中间档问题或应用内字号时补中间档。
- 现有界面整页或全局 CSS 改版：从改动前执行 [改版检查](redesign-checks.md)，先留基线并核对结构与显隐关系，再比较代表页面；不能等交付时只看新版。
- 主题、材质或动效改动：增加实际支持的明暗主题、透明度或动态效果降级检查。浅色产品不要求新增暗色模式。
- 审计器自身改动：运行 `node tests/regression.mjs`。

使用当前环境允许的浏览器与项目已有测试。下列脚本是可选辅助；缺少 Node/Chrome 或被环境限制时采用等价检查，并说明未覆盖的检测。不要为满足脚本要求改变用户选择的工具。主题设置脚本不等于浏览器缩放，根字号变化也不覆盖所有缩放行为。

## 一、工具

```
scripts/detail-audit.js    注入式检测器（无依赖），调用 AUDIT() 返回五类检测 + severity 分级
scripts/audit-runner.mjs   单档运行器：真实浏览器（CDP）打开 URL 或本地文件，输出单行 JSON
scripts/audit-matrix.sh    矩阵运行器：状态 × 视口 × reduced-transparency 全组合逐档检查
scripts/visual-review.mjs  视觉重构对照片：基线 vs 改版逐状态全页截图并排 + 检查点勾选（见 §四）
scripts/ui-self-check.js   当前浏览器中记录组件状态检查和目视结论；未执行项不计通过
```

用法（面向真实应用 URL；状态文件 = 页面稳定前注入执行的 JS）：

```bash
# 每档写一个小 JS，如
echo 'for(let i=0;i<5;i++)document.getElementById("dtPlus").click()' > dt150.js
echo 'document.documentElement.dataset.theme="dark"' > dark.js

./scripts/audit-matrix.sh http://localhost:5173/workbench \
  --dim "dt100.js,dt150.js,dt200.js" --dim "light.js,dark.js" \
  --ready "!!document.querySelector('#app .toolbar')" \
  --assert "parseFloat(getComputedStyle(document.body).fontSize)>=32"

# 单档调试 + 截图目视复核
node scripts/audit-runner.mjs --target page.html --audit scripts/detail-audit.js \
  --viewport 1440x900 --rm reduce --state dt150.js --shot /tmp/check.png
```

`--ready`（应用就绪条件）与 `--assert`（档位生效断言）可透传：**执行过状态脚本 ≠ 覆盖了这个档位**——只有断言目标字号/主题确实生效，才允许采信该档位结果。两者同步/异步统一求值（Promise 等待完成，抛异常或值不严格为 `true` 即判执行失败）。

运行器要点：

- **Chrome 探测**：`--chrome` 参数 → `CHROME_PATH` 环境变量 → 平台常见安装路径（macOS / Linux / Windows）；`audit-matrix.sh` 用 `--chrome` 透传，结果解析只依赖 bash 与 node。
- **支持 URL 与本地文件**：开发服务器页面、具体路由可直接检查；不复制 HTML、不改变相对资源解析。
- **真两态模拟**：`reduced-transparency` 通过 CDP 媒体模拟分别设 `reduce` / `no-preference` 实测（`--rm both` 两态都跑），不靠字符串替换。
- **等待可验证状态**：load 事件 → 注入状态脚本 → `document.fonts.ready` + 双 rAF + 等待全部动画 finished（封顶 3s），不用固定 sleep 赌过渡时长；稳定等待失败按执行失败处理。全流程受 `--deadline` 总时限约束（从进程启动起算，覆盖浏览器启动与连接），超时=失败。
- **退出码**：`0`=全绿；`1`=检出阻断问题；`2`=执行失败（页面打不开/空白/控制台报错/前置断言未满足/AUDIT 失败）——执行失败不能当作通过。
- `--shot <out.png>`（可用 `--shot-at <y>` 先滚动到指定位置；`--shot-full` 输出全页截图而非视口）输出截图，供改过布局的元素目视复核；JSON 结果附 `shot:{w,h,full}`。

## 手动交互检查（自动几何检测不覆盖）

涉及交互时，沿主要流程检查：Tab/Shift+Tab 可达、焦点可见、按控件语义激活；模态打开/关闭/还原焦点；错误与输入关联；异步结果向辅助技术可感知。实际用过屏幕阅读器才能声称读屏验证通过。文字对比度和业务结果需独立验证，不从几何检测结果推断。

报告资源使用每次生成独立的目录；分发时保留 HTML 及其资源目录。重新生成不会沿用旧评审。备注与判定在当前浏览器保存；退化/备案缺理由不计已判。

## 二、五类检测与 severity

| 类别 | severity | 判定 |
|---|---|---|
| `overflowX` 页面水平溢出 | blocked | `scrollWidth - innerWidth > 0` |
| `clip` 文字被裁 | blocked（可见比 <0.6，内容不可读）/ warn（0.6~0.95，轻微切边） | **该段文字自身**裁剪后的可见面积比（在滚动容器处停止；豁免须带证据、记入 `skipped[]`，候选不静默消失——见下） |
| `tight` 行高偏紧 | warn | `line-height < 字号 × 0.95`（固定 px 行高不随字号缩放时出现） |
| `overlap` 文本重叠 | warn | 两个文本矩形横向重叠 >35% 且纵向 >50%，且重叠中心处双方均可见；重叠中心在视口外的标 `offscreen` 报出——待滚动到该处复核，不等于已确认缺陷 |
| `wrapped` 折行异常 | warn | 含 CJK 的短文本 ≥2 行且存在 ≤2 字符的行（孤字/拆词） |

**已知例外**（处置原则：合法遮挡、允许滚动的数据区、明确设计的截断且有完整内容入口）。**豁免不静默**：检测器把全部豁免记入输出的 `skipped[]`（元素、原因、证据），复核时逐条查看"ⓘ 豁免 N 项"清单；证据不足的候选照常报出：

- 零高度收起容器（accordion 关闭态）内的内容——**须有展开入口证据**：`<details>`、`aria-expanded` 控件（自身/祖先/**兄弟结构**，如 button 紧跟零高度面板）。证据取值 `details` / `details-ancestor` / `aria-expanded` / `aria-expanded-ancestor` / `aria-controls` / `aria-expanded-sibling`，记 `skipped` 原因 `collapsed`；**邻接兄弟属弱证据**——按钮没有 `aria-controls` 指向该面板（或其容器）时可能是控制别的菜单的按钮，不豁免而是降级 `warn`「待复核」；裸零高度容器（用户没有任何展开路径）照报；
- `auto/scroll` 滚动容器内的裁切（滚轮、表格横滚）——**仅"内容超出滚动区、可滚动到达"这一种情形豁免**；文字在滚动区内被**内层容器**裁掉（内层裁切可见比 <0.95）照报并注明"滚动区内被内层裁切"；**滚动区自身被外层裁切**（可见比 <0.6）也报——滚不动也看不全；
- transform 位移出容器的元素——**只有伴随「运行中」动画证据（playState=`running` 的 CSS animation / WAAPI）**的位移才豁免（`transform-transient`，动效舞台瞬态）；静态位移、已结束（`finished`，如 fill-forwards 停在视口外）、已暂停（`paused`，被冻结的跑马灯）的动画位移照报——留在原地的裁切是真实缺陷；
- 被不透明层盖住的下层文字（弹层遮挡）——不构成可见冲突；
- 不可见子树（display/visibility/opacity 链）——完全不参与检测；动画元素正常参与，裁切是否瞬态交上面的动画证据判定。

检测器的误报规避逻辑（改检测代码前必读）：只遍历直接子文本节点、逐字符 Range 测行、行聚类用邻近算法、含 `<br>` 豁免、80 字符上限、CJK 门卫、不可见子树跳过——细节见 `detail-audit.js` 文件头。**改动检测器后必须跑 `node tests/regression.mjs`**：正反例（含 finished/paused 动画、滚动区内层裁切、无关联 sibling、pre-wrap 零面积矩形等）与运行器失败路径（异步断言为假/抛异常/超时必须 `exit 2`）会在这里拦截误报、漏报与误通过。

## 三、扩展验收矩阵（按 §0 选择相关维度）

- **字号/缩放**：通常检查默认与 200%；有应用内字号或中间档风险时补 150% 等相关档位
- **外观 × 降级**：只覆盖产品支持的主题；涉及透明材质时检查 reduced-transparency 开/关
- **视口**：响应式页面加窄视口（320-390px）
- **数据状态**：空态、加载中、长文本、异常——页面能呈现的状态尽量覆盖

**分级验收**（不是"全 0 才通过"）：

- **阻断问题清零、警告已处置** → 该检测范围通过；不代表视觉、内容完整性或交互通过
- **警告逐项复核**，每项记录三种处置之一：修复 / 判定无碍 / 备案为例外
- **例外备案要写理由**（如"横向滚动数据区"）；若给检测器加了新豁免，同步更新本节列表

## 四、视觉重构验收（布局或视觉系统改版时使用）

**边界**：几何检测不判断设计收益，也不知道原本应该可见的内容。被 CSS 隐藏的提示可能完全不参与检测；页面没有横向溢出，卡片内部仍可能逐字折行。必须结合原版状态、截图与真实操作判断。

**改版验收流程**：按 [改版检查](redesign-checks.md) 保留同一内容、角色、窗口、缩放和状态的前后截图，实际查看后记录结果。可用以下脚本或当前浏览器生成；不能生成时说明限制，不伪称完成视觉验收。脚本是可选工具，前后比较不是可省略的交付依据。

```bash
# 状态脚本：登录后的界面先注入进入（复用 audit-runner --state 语义）
echo 'document.querySelector(".login-role").click()' > /tmp/vr-enter.js
node scripts/visual-review.mjs \
  --base <原版.html|url> --test <改版.html|url> \
  --states "/tmp/vr-enter.js,..." --out /tmp/visual-review.html
```

浏览器打开对照片，**逐行**（每个页面类型/状态一行）完成 5 项检查点判定（通过/退化/备案 + 备注）：

1. **层次保留**：内容分组与主要操作是否清楚；底色、边框、留白、字号或对齐都可建立层次，不用单一亮度差阈值判断好坏，也不强制每个区块加卡片和阴影；
2. **语义权重**：告警/危险 > 普通信息 > 中性内容的视觉对比强度，改版前后不许降级——降噪不等于把语义差异一起抹掉；
3. **布局密度**：比较首屏信息、字段可读宽度和操作路径；允许在授权改版中调整列数、排列与行高，说明收益，不能把拥挤或大片无用留白当作风格；
4. **色彩信息**：强调色的信息含量（哪个角色权限高、哪个状态异常）不因统一配色而丢失；
5. **整体观感**：拿远看（缩小浏览器）轮廓与重心的第一印象是否仍成立。

**判定纪律**：已确认的内容丢失、不可读或操作不可达必须修复，未修复不算通过；非功能性的设计取舍可备案，但写明位置、理由和代价。**几何检测全过不能替代本节，也不能替代交互检查**。执行者实际查看截图后记录判定，不强制新增人工审批步骤；未看过截图不得声称“已验证无退化”。

## 五、核心纪律

1. **单档位通过不构成交付依据**：某些事故只在特定档位窗口出现（实测过只在某中间档拆、相邻档正常的案例），须按矩阵覆盖；但不要把个别页面的经验写成"所有页面必然发生"的事实。
2. **修复后检查受影响档位**：全局 token、布局或公共组件变化时扩到相关矩阵；局部改动不重复与之无关且仍有效的验证。
3. **改过布局的元素目视复核**：检测器抓的是几何事实，不判断"这样修好不好看"。截图确认观感没退化；**整页视觉改版**升级为 §四 的对照片流程（逐行勾选，不许一句"已复核"带过）。
4. **优先根因、防过度修复**：修之前先查固定高度、最小宽度、不可收缩子项、不合理的单行限制——多数事故是布局根因，不是"缺一个档位特判"。不要为通过某档顺手改掉其他状态下原本正确的布局（实测事故：1.5x 原本正常的六列色卡被改成 3 列）。
5. **检测覆盖的是当前 DOM**：虚拟滚动列表只有已渲染的行参与检测，未渲染数据不在覆盖范围——这类页面在验收记录中写明覆盖边界，"检测通过"≠"全部数据通过"。

## 六、修复决策树

| 症状 | 常见根因 | 修法（根因优先） |
|---|---|---|
| `clip` 文字被裁 | 固定高度/宽度装不下放大或重排后的文字 | 容器高度自适应；尺寸改相对单位；确需固定时给内容留伸缩空间 |
| `wrapped` 短标签拆行 | 容器过窄装不下完整短语 | ① 优先让容器重排（放宽/换行/调整网格）；② 只对真正需绑定的短语局部 `nowrap`（容器 `flex-wrap:wrap`，放不下就换行）；③ 超长单元拆成语义片段 |
| `wrapped` 段落孤字 | 行尾落单字 | `text-wrap:pretty` / `text-wrap:balance` |
| `tight` 行高偏紧 | 固定 px 行高不随字号缩放 | 行高改无单位值或相对单位，随字号自然缩放 |
| `overlap` 文本重叠 | 固定 px 容器装不下放大后的字 | 容器自适应，检查所有固定尺寸部件 |
| `overflowX` 水平溢出 | 元素最小宽度 > 容器 | 移除 `min-width`/放宽 grid 列数；长字符串用 `overflow-wrap:anywhere` 应急断行或就地滚动容器 |
| 表格被长词撑横滚 | 单元格内专名不可拆 | 表格整体 `overflow-x` 滚动属**已知例外**；但内页不应因此产生页面级溢出 |

**修法优先级**：布局根因（自适应高度/相对单位/允许重排）> 局部内容保护（nowrap/anywhere）> 状态隔离（媒体查询或类）> 改字号数值（最后手段，会破坏设计比例）。

## 七、常见系统性根因（实战积累）

1. **固定 px 与单行限制是字号问题的第一嫌疑**：默认架构应是——文字用相对尺寸、文本容器优先自适应高度、布局允许换行和重新分栏、应用内字号设置按产品需要增加。不要把某个项目的 `--dt` 缩放变量推广成所有网页的默认架构；也不要把"修复 180% 的问题"固定解释为"添加一个只在 180% 生效的类"。注意三项验收不要混为一谈：**文字放大**（用户能放大文字）、**页面重排**（等效视口下内容重排）、**文字间距覆盖**（用户覆盖行高/字距后不丢内容或功能）——WCAG 分别要求，不是单个缩放系数能代替的三件事。
2. **先检查 CSS 级联**：普通行内声明通常优先于普通类规则，媒体查询不会自动提高优先级。确认实际生效声明后，只把需要响应式变化的属性移到类规则或变量；不要无差别清理行内样式。
3. **死规则**：写了 `body.dt-lg .sw-grid{...}` 但页面里所有网格都带更高特异性的 `.sw6`——规则永不生效。加规则后 grep 确认特异性链路，或直接实测该档位是否变化。
4. **动态写入组件的时机**：JS 在动画循环里持续写 DOM 的组件（转轮、计数器），要等状态稳定后再读（运行器会等字体与动画完成）；对手写注入脚本，确保先触发状态再等动画结束。
5. **`text-wrap:balance` 的行数上限**：中英混排长段落里有浏览器行数上限（超出即静默失效），长文案仍可能孤字——以矩阵实测为准，不假设规则生效。

## 八、和 web-adaptation.md §4 的关系

§4 讲**对策**（中文换行、nowrap 保护、应急断行的写法），本节讲**验证**（怎么确认对策在全部状态真的生效）。写之前读 §4，交付前跑本节矩阵。
