# HRAS 企业工作台设计模式

适用于需要反复查找、核对和处理业务数据的桌面 Web。先读项目设计系统；这里的视觉配方只在用户选择 HRAS 风格或新建同类工作台且无既有设计系统时采用。不强制用于品牌网站、消费 App 或移动页面。

## 1. 来源与取舍

`HRAS-OBSERVED`，读取于 2026-09-21。源项目为 Payroll-Automated-VC，参考本地工作树，不声称代表已部署生产版本：

| 来源 | 定位 | 提取内容 |
|---|---|---|
| HRAS `DESIGN.md` | 本地 New project 2，设计规范 alpha | 冷灰白画布、蓝色框架、轻质面板、紧凑字号、业务语义 |
| 国内劳务模块工作树，HEAD `cc9bcaea` | `bonus_platform/static/domestic-labor.html`：`.dl-topbar`、`.dl-subject-hero`、`.dl-subject-grid`、`#recentBatchTable` | 科目入口首页、规则版本入口、验证中状态、最近批次 |
| 社保模块工作树，HEAD `3e726ccb` | `bonus_platform/static/social-insurance.html` 和 `social-insurance.css`：`.batch-console`、`.stage-rail`、`.workspace-grid` | 批次控制、审核主区、输出辅区、状态计数、字段视图 |

这些来源不完全相同：设计规范允许 20–28px 大面板圆角，具体页面也使用更紧凑圆角；规范提到深蓝框架，但页面顶栏可以是白色或浅色玻璃。提炼“蓝色承担导航和主操作、浅色承担内容”，不要求所有顶栏涂深蓝。

不复制员工信息、真实业务规则、产品 logo、内部 API 或源代码中的历史 CSS 覆盖链。源码中的小字、弱对比与自定义控件也不是自动通过无障碍的范例。

## 2. 两种结构，按任务选

### A. 模块入口首页（国内劳务首页）

```text
紧凑品牌/模块导航                         账户与帮助
模块标题 + 一段任务说明                 规则版本/说明入口
可执行科目入口网格（范围、名称、说明、可用状态、进入动作）
最近批次（月份、范围、结果状态、时间、继续/查看）
```

核心价值是“知道从哪里开始，并能接着上次的工作继续”。入口卡片是导航，不是假 KPI。卡片区按模块数量和文字长度排布，标题与动作对齐；不要为了凑满网格虚构模块。验证中、可用、未开放必须文字区分，不能仅换颜色。

观察到的首页视觉：三列入口网格、14px 间距、约 18px 卡片圆角与 20px 内边距；介绍面板使用很浅的冷蓝渐变、淡点阵和轻阴影，标题为 34–46px，入口卡片约 160px 起高。这些使“选择科目”成为清晰主角。复用时保留冷蓝层次与标题/卡片的比例，不强制点阵、渐变、三列或固定高度；窄窗口需重排，长说明不照抄源码的 nowrap。

首页可以有较宽的介绍区域，但不能让入口被装饰挤出首屏。已有状态未知时显示占位，不用虚构的“自动化率 99%”。规则版本入口可泛化为帮助、模板说明或处理口径入口；不要把薪酬规则和金额搬到其他产品。

### B. 批次审核工作台（社保报盘）

```text
稳定顶栏：品牌 / 当前模块 / 规则与返回
批次控制：周期、主体、确认日期等必要条件 + 生成/加载动作 + 当前结果时间
流程进度 + 当前批次统计
审核主区（弹性宽度）                    输出与办理（桌面约 300–320px）
  搜索 + 状态筛选及数量                  办理去向/目标
  业务视图 / 模板字段 / 源数据视图        生成前校验及阻塞原因
  审核表格 + 明确行操作                  上传模板/生成结果/人工确认
  结果数与横向滚动入口
```

视觉层次参考：顶层批次面板、流程/统计组合面板、审核主面板分别用圆角白底和轻边界分组；右栏用一条深蓝标题带建立次级重心，下方白卡按办理顺序排列。工具栏用浅底承载筛选，与白底数据区区分。深蓝集中在行动和输出区域，不能把所有面板染蓝。

同一批次的条件、结果时间和生成状态要能对应起来。切换条件后标明旧结果属于哪个范围，防止看着新筛选条件下载旧文件。

把“记录范围”“字段视图”“对记录执行动作”分组。切换字段视图不应隐式清空筛选。颜色对应语义：蓝色为选中与行动，绿色为可处理，琥珀色为待确认，红色为失败或阻塞；统计与筛选使用相同口径。

流程条表达真实状态，不是假装可点击的导航。原页面的五阶段来自其业务，迁移时使用目标业务的阶段。后台生成文件、人工确认、外部提交是不同状态，不能在下载时直接显示“已完成办理”。

右栏为当前任务提供下一步，不能堆无关卡片。宽度不足时放到审核区下面，保留可发现的操作入口；参考页面在约 1160px 收为单列，这是观察值，不是所有项目的断点。

## 3. 视觉配方

以下为 HRAS 观察值及 `PROJECT-DEFAULT` 适配建议。采用已有 token 名，避免并列创建第二套系统。

| 角色 | HRAS 参考值 | 使用方式 |
|---|---|---|
| 页面 / 面板 / 弱底色 | `#eef3f7` / `#ffffff` / `#f8fafc` | 画布与内容分层，表格保持稳定底色 |
| 正文 / 次要文字 | `#101828` / `#667085` | 正文与元信息，浅灰不用于关键提示 |
| 品牌 / 主操作 | `#1e3a8a` / `#2563eb` | 品牌结构与选中、链接、主按钮 |
| 选中底色 / 文字 | `#eff6ff` / `#1d4ed8` | 浅蓝承载选中状态，附边框/勾选 |
| 成功底色 / 文字 | `#ecfdf5` / `#0f766e` | 可继续处理的状态 |
| 警告底色 / 文字 | `#fffbeb` / `#9a6700` | 待确认、不完整；比页面原有不同警告色统一的建议 |
| 失败底色 / 文字 | `#fef3f2` / `#b42318` | 阻塞与失败 |
| 面板边线 / 控件边线 | `#dfe6ee` / `#cbd5e1` | 弱边框分区；交互轮廓另按对比度验证 |

普通文字按 Web AA 对比度检查实际组合，半透明层按实际合成背景验证。不要直接把 warning 当实色填充再默认配白字。

- 字体：复用现有字体；新建可用 `Inter, Geist, system-ui, "PingFang SC", "Microsoft YaHei UI", sans-serif`。未安装字体会回退，不能假定已经加载 SF Pro。
- 桌面正文参考 13–14px，标签 12px，分区标题 18–21px；主页标题可适当放大，但数据处理页不使用营销级大标题。转为 rem 时以项目根字号为准。
- 桌面控件建议 32–36px 起步，表格行 36–44px 起步；多行内容允许增高，触控模式增大命中区域。紧凑不等于缩到不可读。
- 结构间距 16/24px、内部 8/12px、页边 20–32px 为起点；窗口窄时减少页边，再重排列。
- 小控件 8–12px 圆角，大容器按密度选 16–28px。阴影优先轻微，辅以边框，不给每一层重复投影。
- 轻玻璃可用于导航或外围框架；表格和复杂表单使用稳定白底。禁用模糊时仍有明确边界。
- 数字使用 tabular-nums，金额右对齐并显示币种/单位；0、缺失、加载中分别呈现。

## 4. 可迁移的实现片段

`PROJECT-DEFAULT`，类名仅示意，移植到现有组件并消费项目 token：

```css
.review-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(18rem, 20rem);
  gap: 1.125rem;
  align-items: start;
}
.review-main { min-width: 0; }
.review-table-scroll { max-width: 100%; overflow-x: auto; }
.review-table-scroll table { width: 100%; border-collapse: collapse; }
.amount { text-align: right; font-variant-numeric: tabular-nums; }
/* 根据内容开始拥挤的位置调整，而不是按设备型号。 */
@media (max-width: 72.5rem) {
  .review-layout { grid-template-columns: minmax(0, 1fr); }
}
```

保留原生 table 语义；长表横滚在自身容器内发生。吸顶表头、列固定、抽屉须检查滚动和层级，不能遮挡键盘焦点。模态抽屉提供名称、关闭、Escape、焦点约束和关闭后返回触发点；普通非模态侧栏不锁焦点。

## 5. 正反例与验收

| 容易做坏 | 更合适 |
|---|---|
| 所有首页都放四张大统计卡 | 入口页显示任务入口，审核页显示真实批次统计 |
| 白色背景叠白卡、无边界 | 画布、面板、表头三级关系清楚可见 |
| 为整齐隐藏验证中标签或异常解释 | 保留业务差异，整齐来自对齐和一致间距 |
| 主体名称长就整体缩小字体 | 容器可收缩，长文本换行或提供完整内容入口 |
| 单击下载立刻显示任务成功 | 区分生成、下载、人工确认和外部提交 |
| 改造时逐项复制旧页面代码 | 复用组织方式，修复不适合目标项目的尺寸与语义 |

检查：用户能否找到入口、辨认范围、定位异常、解释禁用原因、恢复失败任务并继续下一步。用长中文主体名、空结果、处理中、部分失败、宽表、窄窗口和放大验证。范围、数量和状态必须一致；没有数据接口时只能声称演示交互完成。
