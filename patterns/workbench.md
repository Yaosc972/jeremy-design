# 工作台模式（数据密集后台）

> **性质**：`PROJECT-DEFAULT` 项目设计模式。本文件是"工作台 / 后台"这类产品的工程约定，不是 Apple 官方模板；与 HIG 冲突处按 Web 口径（信息密度优先）。数据可读性 > 视觉表现。

需要配色、字体、间距、材质与组件组合建议时读取 [企业界面视觉语言](../references/enterprise-visual-language.md)，按当前任务选取，不套用固定页面结构。

## 1. 布局骨架

- **稳定框架**：按导航深度选择顶栏 + 内容区，或侧栏 + 顶栏 + 内容区；单模块不强加侧栏。框架在页面间不跳动。
- **信息密度优先**：工作台不是移动端页面的放大版——行高、控件尺寸可以小于触控优先界面（命中区域仍按 WCAG 目标尺寸条款验收，见 `web-tokens.md` §4）。
- **层级靠位置和对齐**，不靠大圆角和阴影堆叠；一屏内可比较的数据量是核心指标。

## 2. 页面级操作 vs 行级操作

| | 页面级操作 | 行级操作 |
|---|---|---|
| 例 | 新建、导入/导出、批量删除、刷新 | 编辑、查看详情、复制、单行删除 |
| 位置 | 页头/工具栏固定位置 | 行尾固定列（不随内容漂移）；悬停显示是增强，**默认可见或可聚焦触发** |
| 危险操作 | 需确认并说明影响范围（"删除 24 项？"） | 需确认；与常规操作拉开间距 |

- 选中行后出现的**批量操作栏**要显示"已选 N 项"和清除选择的入口。
- 行内操作不超过 3 个主操作，其余进"更多"菜单。

## 3. 筛选

- **常显优先**：核心筛选（状态、时间范围、归属）常显在列表上方；低频筛选进折叠区或抽屉。
- **已选条件可见可清除**：生效中的每个条件以 chip/标签回显，单个可 ×，另有"清除全部"。
- 筛选与搜索组合存在时，明确"先搜索后筛选"还是"与筛选叠加"，并在空结果页说明当前生效的条件。
- 筛选状态尽量进 URL（可分享、可刷新、可后退恢复）。

## 4. 分页与批量选择的范围

- **"全选"的语义必须明确**：默认只选**当前页**；若提供"选择全部匹配项"，显示总数并说明跨页范围。
- 跨页选择要持久可见（"已选 37 项（跨 3 页）"），翻页不静默丢失。
- 分页 vs 虚拟滚动：需要精确定位/分享行号时用分页；纯浏览流可用虚拟滚动，但滚动中键盘焦点与吸顶表头要单独处理。

## 5. 列表与详情保持上下文

- **打开详情不丢列表状态**：优先右侧详情面板/抽屉，保持列表可见；跳转整页时，返回必须恢复滚动位置、筛选与选中行。
- 选中行有明确的选中态；键盘上下移动时详情跟随切换（若详情面板存在）。
- 详情里的编辑保存后，列表对应行就地更新并给出反馈，不整页刷新。

## 6. 数字、时间、单位的统一呈现

- **数字右对齐** + `font-variant-numeric: tabular-nums`（等宽数字，列内小数点对齐可比较）。
- 同一列单位一致：单位进表头（"金额（元）"）或每值携带，不混用。
- 时间统一：绝对时间给明确格式与本地时区（如 `2026-09-17 14:30`）；相对时间（"3 分钟前"）用于近期动态，悬停给绝对时间。
- 阈值与异常需要显式标注（色 + 图标 + 文本，不单靠颜色，见 `accessibility.md`）。

## 7. 空数据 vs 无搜索结果：两种空态

- **首次无数据**（从未创建过）：引导下一步操作（"新建第一个项目 →"），不显示筛选相关文案。
- **筛选/搜索无结果**：显示当前生效的条件 + "清除筛选"入口，不引导"新建"。
- **加载失败**是第三种状态：错误说明 + 重试按钮（见 `states-and-forms.md` §1）。

## 8. 普通数据表格 vs 交互式数据网格

**不要看到后台表格就一律加 `role="grid"`。**

- **普通数据表格**：用原生 `<table>`（`th`/`td`/`scope`），语义已完整，键盘默认按 Tab 进出即可。**大多数管理后台列表都属于这一类。**
- **交互式数据网格**：单元格级别可聚焦、可编辑、方向键在网格内移动、`ctrl+方向键` 跳边界——只有这种才用 `role="grid"` 并按 WAI-ARIA APG 的 grid 键盘模型实现。
- 差异的本质：**交互模型决定语义**。加了 `role="grid"` 就要实现全套 ARIA grid 键盘行为（否则对读屏用户是更差的体验）；只读展示表格用 table 语义更好。

## 9. 与验收的关系

- 表格被长词撑横向滚动属 `detail-audit.md` 的**已知例外**（内页不应因此产生页面级溢出）。
- 空态、加载中、长文本、异常是 `detail-audit.md` 验收矩阵的要求项——工作台的"数据状态"维度尤其不能漏。
